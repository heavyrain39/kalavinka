아래는 너와 내가 같이 작업하던 노동요 생성기 웹 프로그램 기획서와 전체 코드야. 이걸로 계속 작업을 이어가고 싶은데 준비되면 얘기해줘. 바로 작업에 들어가지는 말고, 당면 과제 얘기부터 하자. 그리고 중요한 점 한 가지. 난 코딩 까막눈이야. 함수 하나를 통째로 바꿔 끼우는 정도는 가능하지만, 여러 군데를 수정해야 한다면 그냥 수정된 버전의 전체 코드를 내게 제공해주면 돼. 이걸 기본 원칙으로 삼고 같이 작업에 들어가자.

## 프로젝트 기획서: 노동요 생성기 (Work Song Generator)

**버전:** 0.4 (로컬 환경 전환 및 핵심 라이브러리 확정 - Python, PySide6, Pyo 기반)

---

### 1. 프로젝트 개요

*   **목표:** 반복적이거나 집중을 요하는 작업 시 방해가 되지 않으면서도, **음악적인 깊이, 자연스러운 그루브, 미묘하고 다채로운 변화**를 통해 지루함을 효과적으로 덜어주는 **고품질의 사용자 맞춤형 배경 음악**을 **안정적인 로컬 애플리케이션 환경**에서 생성하고 제공하는 서비스입니다.
*   **컨셉:** 사용자가 선호하는 **장르(내부 코드 진행 풀 선택)**나 BPM 등의 기본 설정을 바탕으로, 내부적으로 구현된 **음악성 중심의 생성 규칙 및 알고리즘**을 통해 **멜로디, 아르페지에이터, 베이스라인, 드럼 비트, 패드(예정)** 등의 레이어를 유기적으로 조합하여 완성도 높은 '노동요'를 **실시간 오디오 엔진(Pyo)을 통해 생성**하고, **안정적인 오디오 출력 시스템(SoundDevice 또는 Pyo 자체 출력)**을 통해 재생합니다. 이를 통해 웹 환경에서 발생하던 **오디오 불안정성("퍽" 소리 등) 문제를 근본적으로 해결**하고 사용자에게 끊김 없는 고품질 사운드 경험을 제공합니다. 생성된 음악은 **미묘한 그루브(향후), 점진적인 사운드 변화(향후), 지능적인 패턴 변화(드럼 필인 등)** 및 **사이드체인 효과(향후)**를 포함하며, 사용자의 '새로운 생성' 또는 설정 변경 시 부드럽게 적용됩니다. 설정 저장/불러오기(로컬 파일 기반), 장르 선택 등을 통해 개인화 경험을 지원합니다.
*   **핵심 가치:**
    *   **집중력 향상:** 비-간섭적 디자인, **안정적인 오디오 재생**, 과하지 않은 변화.
    *   **지루함 방지:** 예측 가능한 변화 속 미묘한 디테일, 점진적 발전, 장르 기반 다양성.
    *   **개인화:** 사용자 설정 존중, 장르 선택, (향후) 커스텀 코드 진행 및 패턴 선택.
    *   **음악적 만족감:** 단순 배경음을 넘어, 듣기 좋은 사운드 품질, 자연스러운 그루브, 풍성한 하모니 추구.
    *   **접근성:** **로컬 애플리케이션** (Windows, macOS, Linux 지원 목표), **`.exe` 등 단일 실행 파일 패키징**을 통해 설치 부담 최소화 목표.

### 2. 대상 사용자

*   장시간 컴퓨터 작업 종사자 (개발자, 디자이너, 작가, 연구원 등).
*   학습/암기 시 배경음악이 필요한 학생.
*   창작/취미 활동 시 영감이나 몰입 환경을 원하는 사용자.
*   기존 배경음악 서비스의 기계적인 반복이나 제한된 선택지에 만족하지 않는 사용자.
*   생성형 음악 및 개인 맞춤 사운드 경험에 관심 있는 사용자.

### 3. 주요 기능 (v0.4 현황 및 예정 - 로컬 환경 기준)

*   **음악 생성 엔진 (Python, Pyo 기반):**
    *   **아키텍처:** Python 코드로 음악 생성 로직을 구현하고, **Pyo 라이브러리**를 사용하여 오디오 신호를 실시간으로 합성 및 처리합니다.
    *   **오디오 안정성:** 웹 환경의 제약에서 벗어나 OS의 오디오 시스템에 더 가깝게 접근하는 **Pyo의 오디오 서버 및 SoundDevice(필요시)**를 사용하여 '퍽' 소리 등 **오디오 끊김 문제를 최소화**하고 안정적인 재생을 목표로 합니다. (현재 Pyo 기본 출력 테스트 완료)
    *   **메인 멜로디:** (미구현 - 로컬 환경에서 Pyo 객체로 재구현 필요) 코드 진행 기반 멜로디 생성 로직 구현 예정.
    *   **아르페지에이터:** (미구현 - 로컬 환경에서 Pyo 객체로 재구현 필요) 코드톤 기반 패턴 연주 로직 구현 예정.
    *   **드럼 비트:** (미구현 - 로컬 환경에서 Pyo 객체로 재구현 필요) 킥/스네어/하이햇 패턴, 스윙/벨로시티 그루브, 필인 로직 구현 예정.
    *   **베이스 라인:** (미구현 - 로컬 환경에서 Pyo 객체로 재구현 필요) 코드 루트 기반 패턴 연주 로직 구현 예정.
    *   **사이드체인 효과:** (미구현) Pyo의 컴프레서 또는 엔벨로프 제어 기능을 활용하여 구현 예정.
    *   **코드 진행:** 장르 선택 기반 시스템 및 다양한 코드 타입 분석 (`getCodeTones` Python 함수 구현 완료) 및 데이터 포팅 완료.
    *   **마스터 이펙터:** (미구현) Pyo의 컴프레서, 리버브, 딜레이 등 이펙터 적용 예정.
    *   **노이즈 배경음:** (미구현) Pyo의 노이즈 생성기 활용 및 UI 토글 연동 예정.
    *   **패드 레이어:** (미구현 - 중기 예정) Pyo 신디사이저 활용 구현 예정.

*   **사용자 인터페이스 (Python, PySide6 기반):**
    *   **GUI 라이브러리:** **PySide6** (LGPL 라이선스)를 사용하여 데스크톱 애플리케이션 UI 구축.
    *   **기본 UI 구성 완료:** 메인 창, 섹션 제목, 버튼(재생/정지, 새로운 생성, 저장 등), 슬라이더(BPM, 볼륨), 라디오 버튼(악기), 드롭다운(장르), 체크박스(노이즈) 등 웹 버전과 유사한 레이아웃으로 기본 UI 요소 배치 완료.
    *   **이벤트 처리:** UI 위젯(버튼 클릭, 슬라이더 조작 등)과 Python 코드(콘솔 출력) 간의 기본적인 시그널/슬롯 연결 테스트 완료.

*   **사용자 제어:**
    *   **BPM 조절:** (UI 구현 완료, 오디오 연동 필요) PySide6 스핀박스/슬라이더와 Pyo 시퀀서 연동 예정.

    *   **새로운 생성:** (UI 구현 완료, 오디오 연동 필요) PySide6 버튼 클릭 시 새로운 음악 생성 및 재생 로직(Pyo 객체 재구성 및 시작) 연동 예정.
    *   **마스터 볼륨 조절:** (UI 구현 완료, 오디오 연동 필요) PySide6 슬라이더와 Pyo 마스터 출력 볼륨 연동 예정.

*   **사운드 요소 설정:**
    *   **메인 악기 선택:** (UI 구현 완료, 오디오 연동 필요) PySide6 라디오 버튼 값에 따라 Pyo 신디사이저 타입 변경 로직 구현 예정.
    *   **장르 선택:** (UI 구현 완료, 오디오 연동 필요) PySide6 드롭다운 값에 따라 코드 진행 풀 선택 로직 연동 완료 (재생 시 반영).
    *   **노이즈 배경음 토글:** (UI 구현 완료, 오디오 연동 필요) PySide6 체크박스와 Pyo 노이즈 객체 제어 연동 예정.

*   **루프 저장/불러오기 (로컬 파일 기반):** (미구현 - 단기 우선 예정) 현재 설정을 로컬 파일(JSON, Pickle, INI 등)에 저장하고 불러오는 기능 구현 예정.

*   **웰컴 프리셋:** (미구현 - 단기 우선 예정) 추천 설정을 로드하고 적용하는 기능 구현 예정.

### 4. 사용자 흐름 (User Flow - 로컬 환경 기준)

1.  사용자가 **로컬 컴퓨터에서 노동요 생성기 애플리케이션(`exe` 등)을 실행**합니다. 초기 UI가 표시됩니다.
2.  (향후) '웰컴 프리셋' 즉시 적용 가능.
3.  **장르** (Lo-fi 등) 선택 (코드 진행 풀 결정). 또는 (향후) **커스텀 코드 진행** 입력.
4.  메인 악기, BPM, 볼륨 등 세부 설정 조절.
5.  '재생' 버튼 클릭 → 현재 설정 기반 음악을 **Pyo 엔진으로 실시간 생성 및 안정적으로 재생 시작**.
6.  **루프 진행률 바** 및 **마디별 코드 라벨** 확인 **(현재 미구현)**. (향후) 오디오 파형/스펙트럼 시각화 확인.
7.  '새로운 생성' 버튼 클릭 → 현재 재생 중인 Pyo 객체 정지/해제, 현재 장르 내 **다른 코드 진행 랜덤 선택**, 새로운 Pyo 객체 구성 및 **안정적으로 재생 시작**.
8.  (향후) **자동 전환 옵션** 활성화 시 루프 자동 변경 (페이드 효과 포함).
9.  (향후) 설정 '저장', '불러오기'.
10. '정지' 버튼 또는 창 닫기로 종료.

### 8. 개발 방식

*   **바이브 코딩 (LLM 협업):** 기획/피드백(사용자) ↔ 코드/설명/아이디어(LLM) 상호작용. **LLM이 Python 코드 생성 및 PySide6/Pyo 라이브러리 활용을 주도**하며, 사용자는 기획, 테스트, 피드백 제공 및 코드 복사/붙여넣기/실행에 집중.
*   **단계적/점진적 개발:** 로드맵 기반, 기능 단위 구현 및 테스트/개선 반복. (현재 로컬 환경 전환 및 기본 설정 완료, 핵심 기능 구현 단계)
*   **코드 제공 원칙:** 사용자 편의를 위해 수정된 **함수 또는 클래스 코드 블록**을 제공하는 것을 기본으로 하되, 전체 구조 변경이나 복잡한 수정 시에는 **전체 파일 코드**를 제공.

### 9. 음악성 향상을 위한 핵심 고려 사항 (프로듀서 관점 - Pyo 환경)

*   **하모니:** 다양한 코드/텐션 활용, 안정적인 `getCodeTones`, Pyo를 활용한 풍성한 보이싱 구현.
*   **멜로디:** 스케일/프레이징, 리듬/쉼표 활용, 음역대 제어, 자연스러운 연결 (Pyo 시퀀싱 기능 활용).
*   **리듬:** **로컬 오디오 엔진(Pyo)의 안정성 활용.** 벨로시티/스윙/고스트노트/필인으로 '인간적인' 그루브 구현 (Pyo 패턴, 트리거 활용). 베이스와 멜로디의 리듬 조화. **사이드체인 효과 구현 (Pyo 컴프레서/엔벨로프 활용).**
*   **사운드 디자인:** 레이어링, Pyo 신디사이저/샘플러 패치 개선, 섬세한 이펙터 활용.
*   **구조와 변화:** 안정적인 루프 기반 위에서의 미묘하고 점진적인 변화 (Pyo LFO, 컨트롤 시그널 활용).
*   **믹싱/마스터링:** 각 파트 밸런스, Pyo 마스터 컴프레서/EQ 등 활용.

### 11. 고려 사항 (v0.4 로컬 전환 기준)

*   **실행 환경:** 사용자 컴퓨터에 **Python 설치 및 필요한 라이브러리(PySide6, Pyo 등) 설치 필요**. 향후 **패키징(PyInstaller 등)을 통해 단일 실행 파일 배포**로 설치 부담 완화 목표.
*   **오디오 안정성:** 로컬 환경 전환으로 웹 환경 대비 **안정성 크게 향상 기대**. 단, 사용자 시스템의 오디오 드라이버나 하드웨어 성능에 따라 여전히 문제가 발생할 수 있음.
*   **크로스 플랫폼:** Python, PySide6, Pyo는 크로스 플랫폼을 지원하지만, 운영체제(Windows, macOS, Linux)별로 미묘한 차이나 버그가 발생할 수 있음. **패키징 시 OS별 빌드 필요**.
*   **성능:** 로컬 환경은 웹보다 성능 면에서 유리할 수 있으나, 복잡한 Pyo 객체 사용 시 여전히 최적화 필요.
*   **라이브러리 의존성:** PySide6, Pyo 등 외부 라이브러리 버전 관리가 중요. 버전 업데이트 시 호환성 문제 발생 가능.
*   **개발 복잡성:** 웹 코드 재활용 불가. Python, PySide6, Pyo 등 새로운 기술 스택 기반으로 재구축 필요 (LLM 협업으로 부담 완화).
*   **GUI 디자인:** 웹 CSS만큼 유연한 스타일링이 어려울 수 있음. Qt 스타일시트 또는 커스텀 위젯 구현 필요.
