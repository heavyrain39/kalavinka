# WORKSONG prototype 0.3 — 2026-10-03

## 제품의 중심

사용자가 작곡 설정을 공부하지 않고 작업에 들어갈 수 있게 한다. 음악의 성격을 먼저 선택하고, 소수의 조작으로 밀도·온도·변화를 조절한다. Mastermind의 정밀한 그리드, 무채색 팔레트, 페이더, 각진 패널을 사용한다.

음악은 완전히 무작위로 만들지 않는다. 기능적 화음과 보이스 리딩 위에 4마디 단위의 질문·응답 프레이즈, 코드톤으로 해결하는 경과음, 장르별 베이스와 타악기 셀을 조합한다. 큰 소개 문구와 반복되는 부제 없이 음악 조작부를 중심에 배치한다.

## 음악 계약

| 프로필 | 기본 속도 | 화음의 길이 | 악기와 흐름 |
| --- | --- | --- | --- |
| Warm desk | 78 BPM | 화음 2마디, 편곡 32마디 | 스윙 타악기, 질문·응답 프레이즈, 근음·3음·5음과 접근음, 일부 구간의 약한 덕킹 |
| Quiet space | 64 BPM | 화음 4마디, 편곡 64마디 | 긴 패드, 느린 근음·5음, 드문 멜로디와 아르페지오, 기본 타악기 꺼짐, 덕킹 없음 |
| After hours | 108 BPM | 화음 2마디, 편곡 32마디 | 엇박 베이스, 킥과 연동한 베이스 버스 덕킹, 비트가 쉬는 구간과 아르페지오, 필터 딜레이 |

- 4/4, Strudel 한 사이클 = 한 마디. cycles/second = BPM / 240.
- 시드는 네 가지 조성과 두 가지 authored 진행 중 하나를 결정한다.
- 음역을 제한하고 이전 화음과 가까운 전위를 골라 상성부가 급격하게 튀지 않게 한다.
- 멜로디의 중심음과 아르페지오는 현재 코드톤을 사용한다. 약박의 경과음은 조성 안의 음이며 다음 코드톤으로 순차 해결한다. 베이스는 근음·3음·5음을 사용하고 로파이에 다음 근음으로 이어지는 접근음을 더한다.
- 화음은 2마디 또는 4마디 동안 유지하고 장시간 재생 중 조성을 바꾸지 않는다.
- 32·64마디의 도입·그루브·비움·복귀 구조 안에서 음표 수, 음높이, 간격, 아르페지오와 타악기를 전개한다. 변화 값은 다음 편곡에서 프레이즈·베이스·타악기 셀 변형을 선택할 확률이다.
- 변화 0에서는 음표와 연주 패턴이 정확히 반복된다. 음소거가 다른 파트의 난수에 영향을 주지 않는다.
- 프레이즈 끝에 작은 스네어 고스트 노트를 허용한다. 밝은 크래시, 과한 필인, 상시 비닐 잡음은 넣지 않는다.
- 덥의 킥은 베이스 합산 버스의 독립 GainNode를 짧게 줄이고 복귀시킨다. 로파이는 일부 구간에만 약하게 적용한다. 타악기 음소거 시 예약된 덕킹을 취소하고 베이스 게인을 복귀시킨다.
- 베이스의 게이트와 릴리스를 다음 음 시작 전에 끝내 단음 저음이 겹치지 않게 한다. v2 멜로디의 릴리스는 장르에 맞게 조정하고 아르페지오는 짧게 발음한다.
- 신호에 공격·감쇠·서스테인·릴리스 엔벨로프를 적용한다. 볼륨과 레이어 버스는 짧게 램프한다.
- 리버브와 피드백 딜레이 리턴의 저음을 줄인다. 피드백은 고정 0.27로 제한한다.
- 프로필·시드 전환은 650ms 크로스페이드한다. 서로 다른 조성의 짧은 겹침은 프로토타입의 청취 검토 대상이다.

## 정적 구조

`UI → Settings → 결정적 음악 이벤트 → Strudel Pattern/Cyclist → Web Audio 합성 → 출력`

Strudel 핵심 모듈만 직접 import한다. npm의 umbrella 엔트리는 REPL과 부가 합성기까지 불러오기 때문에 초기 코드와 코드 평가 경로를 줄이기 위해 사용하지 않는다. 공식 엔진 파일을 수정하지 않는다. 버전과 package-lock을 고정한다.

AudioWorklet은 코드 문자열로 생성하지 않고 번들에 포함된 JS 파일로 배포한다. 이 방식은 추후 Manifest V3 탭 기반 확장에도 재사용하기 위한 선택이다. 실제 크롬 확장 빌드와 웹스토어 심사는 이번 웹 프로토타입의 완료 조건이 아니다.

활성 음악의 이벤트 캐시는 최근 마디만 유지한다. 소스는 종료 시 disconnect하며, 새 흐름으로 바뀐 오디오 그래프도 정리한다. 정지 시 AudioContext를 suspend한다. 파형은 장식용 난수 대신 실제 analyser 데이터를 사용한다.

`src/music-v1.ts`는 기존 생성 규칙을 보존한다. 버전 없는 기존 링크·즐겨찾기는 v1으로 읽는다. 일반 실행의 현재 설정은 v2로 복사하고 즐겨찾기 원본은 변경하지 않는다.

## 실시간 마스터링

전체 합산 출력에 28Hz 하이패스, 280Hz의 -1.3dB 저중역 보정, 6.5kHz의 -1.5dB 하이셸프를 적용한다. 입력 게인을 확보한 뒤 1.8:1의 완만한 컴프레서로 믹스를 정리하고, 별도의 빠른 피크 압축과 소프트 피크 곡선으로 최대 출력을 제어한다. 네 레이어의 상대적인 연주 강약과 킥 연동 베이스 덕킹은 그대로 유지한다.

`src/mastering.ts`의 곡선은 로컬 Mastermind의 `src/lib/dsp/limiter.js`에 있는 `applySoftKneeCurve`를 실시간 WaveShaper에 맞게 재사용한다. 무릎 아래에서는 원 신호를 통과시키고, 위에서는 연속적·단조로운 곡선으로 -1dBFS의 점근적 한계에 접근한다. 4배 오버샘플링은 비선형 처리의 앨리어싱을 줄인다. Web Audio 컴프레서의 내부 메이크업 게인과 유한 비율을 고려하므로 피크 압축기의 임계값을 출력 한계로 해석하지 않는다.

볼륨은 처리 뒤에서 0~1의 게인을 조절한다. 따라서 0%는 무음이고 볼륨 변경으로 압축 강도가 달라지지 않는다. 파형의 표시 배율도 높아진 실제 출력 범위에 맞춘다. 파일 전체의 LUFS 정규화, 무음을 따라가는 AGC, FFT 기반 멀티밴드 처리와 트루 피크 보증은 이 경량 체인의 범위에 포함하지 않는다.

## 검증과 후속 판단

v0.3의 실제 샘플 피크·RMS 비교와 스트레스 조건은 [마스터링 검증](MASTERING_QA.md)에 기록한다.

음악 규칙 테스트: v1 골든 해시, 시드·쿼리 순서 재현성, 장음 중복 방지, 음역·밀도·이벤트 길이 상한, 변화 0의 완전 편곡 반복과 변화 100의 전개, 조성·코드톤·경과음 해결, 베이스 게이트·릴리스 분리, 장르별 비움·아르페지오·덕킹, 음소거와 저장·공유 데이터 검증.

브라우저 검증: 세 프로필의 실제 신호 출력, 덥의 실제 버스 게인 감소와 리듬 음소거 시 복귀, 설정 변경, 새 흐름, 정지 후 소스 정리, 저장과 새로고침, 집중 모드, 키보드·터치 도움말, 데스크탑 1024×600~1440×900에서 스크롤·조작부 잘림 없음, 모바일 320~390px 폭, 배포 주소에서 실행과 요청 출처·로드 후 오프라인 재생 확인. 실제 청취 품질 판단과 장시간 백그라운드 안정성까지 자동 검증이 입증하지는 않는다.

후속 개발의 우선순위는 프리셋 추가보다 청취 품질이다. 사용자 청취 피드백과 긴 재생 검증을 바탕으로 밀도·보이싱·음색을 먼저 개선한다. 이후 탭 기반 크롬 확장, 파일 내보내기, 백그라운드 재생 전용 확장을 순서대로 검토한다.
